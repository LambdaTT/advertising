💬 Commentaries:

Aligns this module with the IAM permissions-domain simplification (IAM v1.3.0) by adopting the
tag-based permissioning standard, and reverts an in-progress switch of target custom filters to
the Customfields module — they remain bound to the Settings module's custom fields.

---

✨ Added:

    ▸ Seed `dbseeds/1795316450_advertising-permissions.php`, registering the module's permission
      tags in `IAM_PERMISSION`: `advertising.advertisement.read` / `.manage` / `.publish`,
      `advertising.targetfilter.read` / `.manage` and `advertising.customfilter.read` / `.manage`.

---

🔧 Changed:

    ▸ Replaced the entity/CRUD permission codes (`ADV_*` R/C/U/D) with tag-based permissions
      enforced via `iam/permission->requireAny()`. Read endpoints accept either the entity's
      `.read` or `.manage` tag; write endpoints require `.manage`; the publish endpoint requires
      `advertising.advertisement.publish`. The media-channel listing stays authentication-only.

    ▸ Module presence is now checked via `ModsManager::modExists('iam')`.

---

🗄️ Schema & custom filters:

    ▸ Reverted the target custom-filter reference back to the Settings module's custom field.
      `ADV_TARGETCUSTOMFILTER` stays bound to `id_stt_settings_customfield`
      (→ `STT_SETTINGS_CUSTOMFIELD`), and value matching reads from
      `STT_SETTINGS_CUSTOMFIELD_VALUE`.

    ▸ Dropped the in-progress switch to the Customfields module: removed migration
      `1767149732_change-custom-filter-ref-table.php` and reverted the `id_cst_customfield` /
      `CST_CUSTOMFIELD_VALUE` references in `routes.php` and `services/advertisement.php` back to
      their `stt` equivalents. Schema and code are now consistent on `id_stt_settings_customfield`.
